01
Cover

표지

0:00 – 0:15
화면 : "오늘비서" 타이틀 + 엄마감동팀 · 조승연 AP

"안녕하세요. 엄마감동팀 조승연입니다."

"오늘은 제가 실제 CS 업무를 하면서 필요하다고 느껴 직접 만들어 본 개인 업무 알림 프로그램, 오늘비서에 대해 간단히 발표드리겠습니다."

TIP · 첫 문장은 여유 있게. 시선은 화면이 아니라 청중에게.
02
Origin

아이디어의 시작

0:15 – 0:45
화면 : GPT 프롬프트 → 구조화 결과 변환 카드

"처음 시작은 6월에 냈던 아이디어였습니다."

"CS 업무는 상담만 처리하는 게 아니라, 상담 이후 다시 확인해야 하는 업무가 계속 생깁니다. 환불 진행 확인, 교환 회수 확인, 구매확정 확인, 주간·월간 마감 업무 같은 것들이죠."

"이런 업무는 몇 시간 뒤, 며칠 뒤에 다시 챙겨야 하는데, 기존에는 개인 기억이나 메모장에 적어두고 확인했습니다."

"이 부분을 AI로 좀 더 체계적으로 관리할 수 없을까 생각했고, GPT에게 '이런 프로그램을 만들 수 있을까' 요청하면서 시작했습니다."

03
Problem

후속 업무의 딜레마

0:45 – 1:10
화면 : 흩어진 확인 목록 카드 (다시 찾기 어려움)

"상담량이 많아지면 적어둔 내용을 다시 확인하지 못하거나, 어디에 기록했는지 찾기 어려운 경우가 생깁니다."

"이 부분을 좀 더 체계적으로 관리하고 싶었던 것이 오늘비서의 출발점입니다."

TIP · 짧게 넘어가는 슬라이드입니다. 앞 슬라이드와 톤을 이어서 담백하게.
04
First Version

초기 오늘비서 프로그램

1:10 – 1:35
화면 : 초기 웹 프로그램 목업 (자연어 입력 / 등록된 알림)

"처음에는 아주 단순하게, 업무 내용을 입력하면 지정한 시간에 알려주는 알림 프로그램을 목표로 했습니다. GPT 사이트 기반으로 웹 프로그램을 만들었고요."

"예를 들어 '내일 오전 10시에 구매확정 확인 알림 줘'처럼 자연어로 입력하면, 일정으로 등록되고 알림을 받을 수 있게 구성했습니다."

05
Workflow Update

웹 알림 → PC 팝업 알림

1:35 – 2:05
화면 : 01 처음 구성 · 02 발견한 한계 · 03 Windows 알림 연동

"다만 실제로 사용해 보니, CS 업무 특성상 웹사이트 창을 계속 켜놓고 있기 어렵다는 문제가 있었습니다. 상담창, 이지어드민, 엑셀 등 여러 화면을 동시에 봐야 하니까요."

"그래서 오토핫키라는 Windows 매크로 프로그램을 함께 사용하도록 수정했습니다. 등록된 알림 시간이 되면 컴퓨터에서 별도 알림창이 뜨도록 만든 거죠. 이후로는 사이트를 계속 보고 있지 않아도 알림을 받을 수 있게 됐습니다."

06
Core Features

추가된 핵심 기능

2:05 – 2:35
화면 : 업무알림 · 공지사항 · 개인메시지 · 브리핑 4개 카드

"이후 단순한 알림 프로그램에서 좀 더 실제 비서처럼 쓸 수 있도록 기능을 계속 추가했습니다."

"출퇴근 시간을 설정하면 오늘 할 업무·잔여 업무·완료 업무를 브리핑 받을 수 있고요. 팀 전체가 알아야 하는 내용은 공지사항으로 등록해 반드시 확인 버튼을 눌러야 꺼지도록 했습니다. 즉각 대응이 필요한 건은 담당자에게 바로 개인메시지로 전달할 수 있습니다."

"지금부터는 이 기능들을 실제로 직접 보여드리겠습니다."

TIP · 마지막 문장에서 자연스럽게 다음 화면(실제 데모)으로 넘어가며 시선을 데모 창으로 이동하세요.

08
Summary

마무리

5:05 – 5:25
화면 : 요약 3카드 + 감사합니다

"오늘비서는 '반복 업무를 잊지 않기 위한 알림'에서 시작했지만, 실제 사용하면서 CS 업무 흐름에 맞춰 계속 수정한 프로그램입니다."

"가장 큰 장점은 개인 기억에 의존하던 후속 업무를 시스템으로 관리할 수 있다는 점, 그리고 자연어로 등록할 수 있어 별도 교육 없이 사용할 수 있다는 점입니다."

"앞으로도 사용하면서 발견되는 개선점을 계속 반영해 나가겠습니다. 감사합니다."
